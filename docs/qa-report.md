# QA acceptance audit (PRD sections 9 and 11)

QA agent H, Oct 26, 2026. This covers the `worktree-agent-a4a29be0d289fc85a` branch (base `78cc5e8`).
It has one row for every checkbox in PRD section 9 (acceptance criteria) and section 11 (App Store
readiness).

PRD 9 says v1.0 is done only when every box is checked **on a physical iPhone and a physical Android
phone**. No physical device and no iOS or Android build were available for this audit. So no row
below counts as checked on a device. "Verified here" means the automated evidence passes in this
repo, on Jest, Node and a headless Chromium web export. The device pass is still owed for every
section 9 row.

## Status key

| Status       | Meaning                                                                                              |
| ------------ | ---------------------------------------------------------------------------------------------------- |
| **Verified** | Verified here by the automated test or command named in the row.                                     |
| **Fixed**    | A defect or gap was fixed during this QA pass, and the fix is verified by the test named in the row. |
| **Device**   | Needs a physical device (development or store build, not Expo Go). Only a person can check it.       |
| **Human**    | Needs a human, store-console or legal action. The row says exactly what to do.                       |

A row can carry more than one status. For example, "Verified + Device" means the logic is covered
here and the on-device behavior is still unchecked.

## Found but not fixed

- **Placeholder app art (release blocker).** The icon, splash, Android adaptive icons and favicon are
  Expo's template images (see P7 and L3).
- **30-pack target depends on After Dark** (see C1 and L4). The release plan needs one decision
  covering both rows.
- **`SHIP_AFTER_DARK = false` only hides the Settings toggle** (`app/settings.tsx`). The adult pack
  JSON is still bundled: the generated `content/packs/index.ts` has static `require`s for `party`,
  `awkward-situations` and `dating`, and the manifest lists them. A family-only build therefore still
  contains adult phrases, and Apple and Google rate what is in the binary. A truly family-only v1
  needs the pack build (`scripts/gen-packs/build.ts`) to leave adult packs out of the manifest and
  loaders behind the same flag. That is a content-pipeline change for the orchestrator; this pass
  did not regenerate content.
- **Maestro flows have never run** on a device or a simulator (P5).
- **Content warning:** `npm run content:validate` reports a near-duplicate in Sports ("Splits" /
  "Split"). Fix it at the source in `scripts/gen-packs/sources/sports.txt` and rebuild. This pass did
  not regenerate content, as instructed.
- **Frozen-contract comment drift** (from the engine handoff). In `src/engine/types.ts`, the state
  diagram says undo "stays caught if in caught", but the engine goes to `scoreboard`. Only the
  orchestrator can edit the comment.
- **Web-only:** expo-router splits routes on web. `_layout.tsx` prefetches the in-game routes. The
  cleaner fix is `['expo-router', { asyncRoutes: false }]` in `app.config.ts` (orchestrator).
